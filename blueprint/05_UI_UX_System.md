# EWES
## Design System (UI/UX)
### Version 1.0 | Statut : Draft

---

# 1. Objet

Le design system rend l'expérience visiteur, gestionnaire et administrateur cohérente, accessible et implémentable comme des composants React réutilisables, en français et en anglais.

# 2. Principes d'expérience

Direction artistique institutionnelle et technique : élégante, sobre, moderne, facile à parcourir. Hiérarchie de lecture nette (l'expertise avant la décoration). Mobile-first sur l'ensemble du site public. Navigation intuitive avec appels à l'action visibles (contact, réalisations). Cohérence visuelle avec l'univers environnement/eau/ingénierie d'EWES (palette sobre, imagerie terrain).

# 3. Fondations

| Famille de token | Standard |
|---|---|
| Couleur | Tokens sémantiques uniquement : primaire, surface, texte, succès, avertissement, danger, désactivé |
| Espacement | Échelle 4, 8, 12, 16, 24, 32, 48 |
| Rayon | 8 pour les contrôles, 12 pour les cartes, 16 pour les panneaux |
| Typographie | Échelle centralisée, hiérarchie distincte titres/corps de texte, lisible en FR et EN |
| Icônes | Icône reconnaissable accompagnée d'un libellé texte pour toute action critique |

> Note (2026-09-29) — palette du site public (`apps/web/src/app/globals.css`) : le bleu acier reste la couleur primaire (pôle Eau, sections immersives) ; chaque pôle a un accent minéral nommé — malachite (Environnement), bleu primaire (Eau), cuivre (Travaux d'ingénierie) — exposé par la variable contextuelle `--pole` (classes `pole-env|eau|ing`, utilitaires `text-pole`/`bg-pole`/`border-pole`). Surfaces : `paper`/`paper-muted` pour les sections de lecture, `night`/`night-deep` pour les sections d'impact (Formation, Contact, footer), avec variantes `*-bright` réservées aux fonds nuit. Contrastes vérifiés : ≥ 4,5:1 sur papier, ≥ 7:1 sur nuit. Chaque pôle a aussi un motif de légende cartographique (`--pattern-env|eau|ing`), jamais utilisé seul pour porter une information (toujours accompagné du nom du pôle).

# 4. Composants partagés requis

Coquille de site (header/footer/sélecteur de langue), bouton primaire/secondaire/destructif, champ de texte, champ de recherche, carte réalisation, carte actualité, filtre de portfolio, chip de statut (publié/brouillon), fil d'ariane, état vide, état d'erreur, squelette de chargement, boîte de dialogue de confirmation, notification toast, bannière hors-ligne/erreur réseau.

> Note (2026-10-02) — **kit du portail livré** : `apps/web/src/components/admin/ui/` (point d'entrée `index.ts`, aucune dépendance ajoutée). `Button` (primary/secondary/ghost/danger, 3 tailles, état « en cours » verrouillé mais lisible), `ButtonLink`, `IconButton` (libellé obligatoire) ; `Field` (libellé, aide, erreur, « facultatif », câblage ARIA automatique) avec `Input`, `Textarea` (compteur), `Select` natif, `Checkbox`, `Switch` — compatibles React Hook Form (`ref` + props natives) ; `BilingualField` (onglets FR/EN, traduction manquante et erreur signalées, bascule vers l'onglet en erreur) ; `SearchInput` + `useDebouncedValue` ; `Badge` et `StatusChip` (libellé et couleur uniques par valeur de l'API : contenu, message, e-mail, confidentialité, cycle de vie, rôle ; accord féminin) ; `SegmentedControl` (filtres avec effectifs) ; `DataTable` (tri `aria-sort`, ligne cliquable, colonnes masquées sur mobile, états intégrés) + `Pagination` ; `Card` ; `EmptyState`, `ErrorState` (message déduit du statut, référence de requête), `Skeleton`/`SkeletonText` ; `Dialog` (élément `<dialog>` natif, focus initial `data-autofocus`, focus rendu) ; `useConfirm()` (attente serveur dans la fenêtre, erreur affichée sans fermer, saisie exigée pour l'irréversible) ; `useToast()` (`toast.error(erreur)` déduit le message) ; `NetworkBanner` (hors connexion). Variantes documentées en direct sur `/admin/composants` (développement uniquement, introuvable en production).

> Note (2026-10-02) — **kit du site public livré** : `apps/web/src/components/public/ui/` (point d'entrée `index.ts`), compatible Server Components. `ButtonLink` (lien localisé), `ButtonAnchor` (fichier, carte, portail `/admin`), `Button` (formulaire, état `pending`), `buttonClass()` pour les liens à composant propre (`ScrollLink`, `DocumentLink`) — tons `paper`/`night` ; `TextLink` (action secondaire soulignée) ; `FilterChip` (filtre de portfolio : lien `aria-current` si porté par l'URL, bouton `aria-pressed` sinon ; formes pilule/carrée) ; `EmptyState` (`framed`/`plain`, papier/nuit, action facultative) ; `Pagination` (liens `rel=prev/next` côté serveur ou boutons côté client, fenêtre 1 … 4 5 6 … 12, libellés partagés `Ui.pagination`) ; `SectionHeading` (niveau `as`, **`h1` sur le titre principal de chaque page** — les six pages internes n'en avaient aucun). Les composants du kit n'imposent pas de marge extérieure. Le bouton a désormais un focus clavier visible (bleu sur papier, malachite sur nuit), un état désactivé et un état « en cours ». Variantes documentées sur `/fr/composants` (développement uniquement, 404 en production). Les cartes réalisation et actualité restent des composants de domaine (`NewsCard`, cartes de `RealisationsGallery`), non génériques.

# 5. Règles d'état et de retour utilisateur

Chaque page à données définit ses états : chargement, vide, erreur, non autorisé. Les boutons de soumission se verrouillent pendant une requête active mais préservent le contexte du formulaire en cas d'échec. Le statut n'est jamais communiqué uniquement par la couleur (toujours un libellé texte associé).

# 6. Navigation publique

Header avec menu principal (Accueil, À propos, Nos services, Nos réalisations, Actualités & publications, Documents, Contact) et sélecteur de langue persistant. Footer avec coordonnées, liens légaux et accès à l'espace documentaire privé.

# 7. Navigation portail d'administration / espace documentaire

Interface de type dashboard : navigation latérale par module (Éditorial, Documentaire, Contacts, Utilisateurs, Tableau de bord). Priorité à la densité d'information et à l'efficacité opérationnelle plutôt qu'à la démonstration visuelle.

> Note (2026-10-02) — coquille du portail livrée (`apps/web/src/components/admin/`). **Thème clair/sombre** propre au portail (le site public reste mono-thème) : tokens sémantiques `canvas`, `panel`, `raised`, `sunken`, `line`, `ink`/`ink-muted`/`ink-subtle`, `brand`, `env` (malachite), `ing` (cuivre), `ok`/`warn`/`bad`, définis dans `app/admin/admin.css` (contrastes ≥ 4,5:1 dans les deux thèmes) ; préférence Clair/Sombre/Système mémorisée par navigateur, posée avant le premier rendu (aucun flash), bascule animée (View Transitions, désactivée si « réduire les animations »). **Mise en page** : barre latérale sur le fond, contenu dans un panneau en relief ; barre latérale repliable en rail d'icônes (touche `[`, menus flottants au survol), tiroir sur mobile ; barre supérieure avec fil d'Ariane, recherche, thème, notifications, menu du compte. **Palette de commandes** (Ctrl K / ⌘ K, ou `/`) : aller à tout écran autorisé ou lancer une action. États standard : squelette de chargement, « accès non autorisé », « page introuvable », écran « en préparation » pour les modules pas encore construits. Navigation complète et règles de visibilité : `14_Admin_Backoffice.md` §2.

> Note (2026-10-02) — **Médiathèque** (`/admin/medias`, `components/admin/media/`) : bibliothèque d'images en **grille de vignettes** (4:3, chargement différé, nom + format + poids) plutôt qu'en tableau — l'œil reconnaît une image avant son nom. Barre d'outils : recherche, onglets **Toutes / Utilisées / Non utilisées** avec effectifs (le nettoyage est la tâche récurrente), tri. **Ajout sans friction** : bouton, glisser-déposer sur toute la page (voile « Déposez vos images »), ou collage d'une capture ; plusieurs images à la fois, file de 2 envois parallèles, suivi à part (`UploadTray`) qui ne liste que ce qui demande attention (en cours, refusé avec sa raison, relance) ; contrôle local du type et du poids avant envoi, l'API restant juge du contenu réel. **Sélection** : case à côté de la vignette (jamais imbriquée dans le bouton), visible au survol/focus, toujours sur tactile et dès qu'une sélection existe ; barre d'actions collante ; suppression groupée qui écarte les images utilisées en le disant. **Fiche** (fenêtre modale, ← → entre images, Échap) : aperçu en grand, dimensions, date, auteur, **où l'image est utilisée** (liens vers l'édition), copier l'adresse, ouvrir, télécharger, supprimer — bouton désactivé **avec explication** si l'image est utilisée. Accessibilité : usage dit en texte (« Utilisée · 2 »), cases 28 px, focus visible, `aria-live` sur les décomptes, mouvements désactivés si « réduire les animations ». **Vignettes** : la grille affiche une vignette WebP de 640 px (`thumbUrl`, `thumbOf(url)` pour les écrans qui n'ont que l'adresse), jamais l'original. **Sélecteur d'images** (`MediaPicker`) : même grille en fenêtre, recherche, pagination, envoi à la volée (l'image envoyée est aussitôt cochée), sélection simple (couverture) ou multiple avec plafond, images déjà utilisées par l'appelant marquées « Déjà ajoutée ». **Galerie d'une réalisation** (`GalleryCard`) : vignettes ordonnées (la première porte « Principale »), un volet de réglage par image (descriptions FR/EN, avancer/reculer, définir comme principale, retirer ; « Sans description » signalé en texte), enregistrement groupé. Limite connue : pas de texte alternatif par défaut sur l'image (il se saisit à l'usage).

> Note (2026-10-02) — **Partenaires et documents d'une réalisation** : mêmes principes que la galerie (brouillon local, enregistrement groupé, « Modifications non enregistrées »). Partenaires : pastilles retirables, saisie assistée (`datalist`) par les noms déjà employés, virgule pour en coller plusieurs, doublon signalé en texte. Documents : liste avec catégorie, année et statut, avertissement en texte si un document n'est pas publié (invisible sur le site), `DocumentPicker` (recherche, pagination, sélection multiple, « Déjà associé »). Écran **Partenaires & bailleurs** : tableau (organisation, nombre, réalisations liées en liens), graphies différentes signalées (« Écrit aussi : … ») avec action « Unifier », renommage et retrait avec confirmation.

# 8. Accessibilité et contenu

Contraste suffisant pour une lecture confortable, texte redimensionnable, libellés en français clair pour le public EWES (RDC), pas d'abréviation non expliquée, dates et unités localisées par langue.

# 9. Critères d'acceptation

Un visiteur comprend l'offre EWES sans tutoriel. Un Gestionnaire publie un contenu sans assistance après la formation prévue. Tout état critique reste compréhensible sans dépendre uniquement de la couleur. Chaque composant réutilisable a ses variantes documentées (état par défaut, focus, désactivé, erreur).

> Note (2026-10-03) — **Pages institutionnelles et Pôles & services** (`components/admin/pages/`, `components/admin/services/`). **Principe : un seul vocabulaire entre la base, le portail et le site.** Un pôle garde partout son identité (`lib/poles.ts` : slug, code ENV/H₂O/ING, accent malachite/bleu acier/cuivre, visuel d'origine) ; le portail reprend le motif de légende cartographique du site (`pattern-swatch`) sur les cartes de pôle, et le texte coloré utilise les jetons du portail (`text-env|brand|ing`, validés en clair et en sombre) plutôt que la couleur du site, pensée pour un fond clair. Une prestation porte son **pictogramme en base** (`icon`, liste partagée `lib/service-icons.ts`) : le site et le sélecteur du portail en tirent le même dessin, et réordonner ne change plus les pictogrammes. **Pages** : liste en tableau (nom, adresse, titre affiché, anglais, statut) ; l'éditeur part des **textes d'origine du site** (route `GET /api/site-pages/defaults`, hors bundle du portail) plutôt que d'une page blanche ; deux cartes (en-tête, référencement avec compteur de caractères visé 70–160) et, à droite, la publication puis un **aperçu en direct FR/EN** de l'en-tête et de l'extrait de moteur de recherche (mêmes règles de repli que le site). Une page non publiée ici n'a aucun effet : le site affiche son texte d'origine, et l'écran le dit. **Pôles** : trois cartes (visuel, code, accroche, effectifs, état de la version anglaise) ; l'éditeur enchaîne Présentation, Visuel (médiathèque, cadrage 4:3 comme le site, texte alternatif FR/EN), Prestations, puis l'identité du pôle en lecture seule. Prestations : liste ordonnée, déplacement par boutons Monter/Descendre annoncés dans une zone `aria-live` (pas de glisser-déposer : clavier et lecteur d'écran), ajout/modification dans une fenêtre avec **aperçu de la carte du site**, sélecteur de pictogrammes en boutons radio natifs, retrait confirmé et audité. Les étiquettes posées sur une photo ont un fond plein (lisibilité).

> Note (2026-10-03) — **Chiffres clés** (`/admin/chiffres-cles`, `components/admin/key-figures/`) : un seul écran, sans liste/fiche (huit chiffres au plus). En haut, un **aperçu FR/EN de la bande** telle que la page À propos l'affiche (seuls les chiffres visibles, même grille que le site grâce à `lib/key-figures.ts` : 1 à 8 chiffres, la dernière cellule d'une ligne incomplète occupe la place restante) ; dessous, la liste ordonnée (valeur calculée, libellé, étiquettes « Masqué », « Calculé depuis 2008 », « Anglais à compléter ») avec Monter/Descendre annoncés, Masquer/Afficher immédiat, Modifier, Retirer (confirmé, audité). La fenêtre d'édition propose **Valeur fixe** ou **Années écoulées depuis…** (le site affiche alors l'écart avec l'année courante, recalculé chaque 1er janvier), suffixe, libellé et précision FR/EN, visibilité, et l'aperçu de la tuile.

> Note (2026-10-03) — **Chiffres clés : origine de la valeur.** La fenêtre d'édition propose une liste « Origine de la valeur » : nombre saisi, années écoulées depuis une année, **nombre de missions référencées** et **nombre de formations réalisées** (comptés en direct sur les réalisations publiées, avec le nombre du jour affiché : « 34 aujourd'hui »). Les valeurs automatiques ne se ressaisissent jamais ; la liste les signale (« Automatique : missions »).

> Note (2026-10-03) — **Experts** (`/admin/services/experts`, `components/admin/experts/`). **Liste** : lignes ordonnées (portrait 3:4 ou monogramme teinté de l'accent du pôle, nom, fonction, pastille du pôle, années, statut), recherche, filtre de pôle, statut avec effectifs ; Monter/Descendre annoncés, **désactivés quand un filtre est actif** (l'ordre est celui de la liste complète, l'écran le dit) ; bandeau qui prévient quand aucun expert n'est publié (la section Équipe disparaît de À propos). **Fiche** (création et modification) : Profil (nom, fonction FR/EN, pôle, années), Présentation (texte FR/EN, **spécialités en pastilles** — Entrée ou virgule ajoute, croix retire, doublons écartés, 12 au plus), colonne de droite : publication (suppression définitive confirmée en saisissant le nom ; pas d'archivage), avancement de la traduction, **portrait** (médiathèque, cadre 3:4 centré haut comme la galerie) et **aperçu en direct FR/EN de la fiche** telle que la galerie la dévoile. Un profil est une personne : brouillon jusqu'à une publication explicite.

> Note (2026-10-03) — **Utilisateurs & rôles** (`components/admin/users/`). Éléments nouveaux : `RolePicker` (cartes radio natives — flèches du clavier, état « Rôle actuel »), `RoleScope` (ce que le rôle permet / ne permet pas, coches doublées d'un libellé pour lecteurs d'écran), `UserAvatar` (monogramme teinté du rôle, grisé si désactivé), `ActivationLink` (lien copiable, retour d'état annoncé). Les trois rôles gardent les mêmes teintes partout (Administrateur cuivre, Gestionnaire malachite, Utilisateur bleu) mais jamais sans libellé. `AuthShell` (`components/admin/auth/`) factorise le cadre commun connexion / activation (carte sur paysage brumeux).

> Note (2026-10-03) — **Journal d'audit** (`components/admin/audit/`). Même langage que les autres listes : tableau dès 640 px, cartes en dessous (`CardList`, désormais dans le kit `ui/`), pagination, états vide/erreur/chargement. Une alerte (accès refusés) se signale par une teinte **et** un chiffre **et** un libellé. Le détail d'une entrée est une fenêtre modale lisible au clavier (Échap, flèches), avec un tableau Avant/Après dont les lignes modifiées sont surlignées et annoncées « (modifié) » aux lecteurs d'écran.
